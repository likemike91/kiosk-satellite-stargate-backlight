# Stargate Backlight for Kiosk Satellite

Turns off the **physical backlight** during Kiosk Satellite's **Black** screensaver or **timed blanking after any screensaver** on the original Shelly Wall Display (Stargate), while Android remains awake. This avoids the normal Android brightness minimum, which can leave a black screen glowing.

Independent plugin using the public SDK. No modified Kiosk APK, app signing changes, root commands, Shizuku, ADB connection, network service or Home Assistant automation is required at runtime.

**Initial experimental release:** automated controller and lifecycle tests are included. Physical screen darkness, wake latency and notification/voice behavior still need validation on real hardware. This plugin does not fix delays after actual Android screen power-off; configure Kiosk as below.

## Compatibility and device detection

- Kiosk Satellite **2026.10.45 or newer**, Android 7 / API 24 or newer. Compiled against the SDK interfaces from Kiosk tag `2026.10.45`.
- Reads the public `getDeviceInfo` response. Accepts an exact `model` of `Shelly Stargate`, `Stargate`, or `SAWD-0A1XX10EU1`, or an exact `device` of `SAWD-0A1XX10EU1`. Comparison ignores case and surrounding whitespace. Friendly device names and substring matches are not accepted.
- Requires the fixed file `/sys/devices/platform/leds-mt65xx/leds/lcd-backlight/brightness` to exist and be readable/writable by Kiosk, and its sibling `max_brightness` to report `255`.
- The file was observed with mode `0666` and SELinux permissive on the target Stargate. Other firmware can differ; the plugin stops with an error if reads/writes fail. It never changes permissions or SELinux policy.
- Other Shelly models are deliberately unsupported. The presence of a similarly named backlight file alone is insufficient.

The model `Shelly Stargate` was supplied by the device owner; verification of all runtime checks on hardware is still pending.

## Install

1. In Kiosk's **Screensaver** settings, enable the screensaver. Choose either setup:
   - **Dark immediately:** select **Black** and set **Turn screen off after** to **0 / disabled**.
   - **Show a screensaver, then go dark:** select any screensaver (clock, photos, website, etc.), set **Turn screen off after** to the desired delay, and enable **Use a black screen instead**. For example: show the clock, then turn the backlight off after one minute.
2. With a nonzero timer, keep **Use a black screen instead** enabled to avoid actual Android screen power-off. Disable external automations that actually power Android's screen off if you want to avoid Android resume.
3. Keep Kiosk's **Keep CPU awake while the screen is off** enabled.
4. With the display lit, open **Plugin Manager**, enable plugins, then add this repository:
   `https://github.com/likemike91/kiosk-satellite-stargate-backlight`
5. Review, trust and install the plugin, then enable it.
6. If you enabled it during an existing screensaver session, dismiss the screensaver once and let a new one start. The plugin waits for an explicit view event before blanking.

Repository installation needs a published release with assets uploaded by GitHub Actions. For a local developer build, use **Plugin Manager → Developer Tools → Install from ZIP**.

## Behavior

The plugin listens to public `screensaver.state`, `screensaver.view`, `screen.state` and `screen.brightness` events. It writes literal `0` to the hardware backlight only while all of these are true:

- The screensaver is active.
- Its visible view is `black` (Black screensaver) or `blank` (timed blanking after any screensaver).
- Kiosk considers the Android screen on.
- Kiosk explicitly reports a panel brightness level of zero.

It samples hardware brightness every 200 ms to remember the awake level and to correct delayed Android writes while blanked. Event callbacks also apply changes immediately. A positive brightness requested by Kiosk for voice, alarms or notifications suspends blanking. The selected screensaver stays visible until Kiosk switches to its timed `blank` state; no separate plugin timer is needed. The common `blank` state works regardless of which screensaver preceded it. A black view with a zero panel level generated by another Kiosk feature follows the same policy.

On dismissal or plugin stop it restores the last observed awake brightness **only if the backlight is still zero**, so it does not overwrite a normal brightness already restored by Android. It restores on recoverable errors where file access remains possible. It does not persist the saved brightness across process death or reboot; Kiosk/Android must restore the backlight on restart. Other apps writing directly to the same backlight may conflict: keep a single app responsible for blanking it.

## Recovery

- The plugin's **Restore backlight** command releases its zero until the next screensaver session.
- Disabling the plugin restores the backlight when its normal shutdown callback runs.
- If Kiosk crashes while dark, or restore cannot write the file, use ADB:

  ```sh
  adb -s DISPLAY_IP:5555 shell 'echo 80 > /sys/devices/platform/leds-mt65xx/leds/lcd-backlight/brightness'
  ```

  `80` is a recovery brightness, not a remembered user setting. On firmware that restricts this file, the command may require additional privileges.

## Build and test

Install Python 3, JDK 17+ and Android SDK platform 35 / build-tools 35.0.0. Set `JAVA_HOME` and `ANDROID_HOME`.

```sh
python3 tools/test.py
python3 tools/build.py --android-platform 35
```

Tests cover hardware identity rejection, actual zero writes, delayed Android writes, normal restore, not overwriting Android's restore, notification/voice brightness lifts, timed blanking after different screensavers, both view/brightness event orders, stop while timed-blanked, initial query/event races, stop/late events, explicit recovery, unsupported devices and I/O failures. CI builds the installable ZIP and checksums. A published `vX.Y.Z` release triggers a tested build and uploads the three files Kiosk's installer expects using `github-actions[bot]`.
